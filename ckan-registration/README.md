# CKAN Registration Workflows

Standalone workflows to register or refresh CKAN datasets.

## Standalone guarantee

This directory is self-contained.
It does not import `semantic_bridge` from elsewhere in the repo.
All required CKAN/auth/LLM helpers are copied locally in `utils.py`.

## What this setup does

### `ckan_registration.ipynb`

- Lets you choose a local resource directory, source metadata URL, and CKAN dataset name.
- Pulls metadata text from the source URL.
- Uses an OpenAI-compatible LLM to propose dataset metadata.
- Checks whether the CKAN dataset already exists.
- If it exists: compares current CKAN metadata vs. source-derived metadata and can patch it.
- If it does not exist: creates it.
- Uploads/upserts local files as CKAN resources.
- Infers model type from filenames/extensions and enriches each CKAN resource with MINT standard variables.
- Optionally removes stale CKAN resources that are no longer present locally.
- Supports CKAN package fields like `author`, `author_email`, `maintainer`,
  `maintainer_email`, `license_id`, `type`, `isopen`, `spatial`,
  `temporal_coverage_start`, `temporal_coverage_end`, and `version`.
- Supports MINT enrichment fields such as `mint_standard_variables` (configurable via `MINT_RESOURCE_FIELD`).

### `notebook_ckan_registration.ipynb`

- Reads a target Jupyter notebook from `NOTEBOOK_PATH`.
- Walks markdown/code source lines and text-like cell outputs with cell and line references.
- Uses one LLM pass to recommend CKAN-useful context from each source/output chunk.
- Combines the retained context with notebook inventory and optional previous CKAN metadata.
- Uses a second LLM pass to propose CKAN package metadata for the dataset produced by the notebook.
- Pulls temporal coverage only from notebook evidence such as variables, dataframe filters, filename date ranges, or printed/displayed output values.
- Normalizes spatial coverage to a GeoJSON `Polygon`/`MultiPolygon`; lon/lat bboxes are converted to closed polygon rings.
- Prompts dataset titles to include supported location, measured quantity, units, and method/source context.
- Uses `NOTEBOOK_SOURCE_URL` or an inferred GitHub blob URL for the CKAN `url` field when available; it does not reuse `SOURCE_METADATA_URL` from the file-registration workflow.
- Blocks the old Yegua/TWDB source metadata URL from the notebook-derived CKAN `url` field, even if it appears in `.env`, previous CKAN metadata, or LLM output.
- Uses `NOTEBOOK_CKAN_DATASET_NAME` and `NOTEBOOK_CKAN_DATASET_TITLE` only when you want to override the LLM-generated package name or title.
- Updates an existing CKAN entry when `EXISTING_CKAN_ENTRY` is set to a dataset name, ID, or dataset URL.
- Creates a new CKAN entry when no existing entry is provided or found.
- Can optionally upload the source notebook as a CKAN resource.

## Files

- `ckan_registration.ipynb` - File/resource registration notebook.
- `notebook_ckan_registration.ipynb` - Notebook-derived metadata registration notebook.
- `utils.py` - Local CKAN/auth/LLM helper functions.
- `.env.sample` - Environment variable template.

## Usage

1. Copy `.env.sample` to `.env` and set credentials.
2. Open either `ckan_registration.ipynb` or `notebook_ckan_registration.ipynb`.
3. Update configuration cell values as needed.
4. Run cells top to bottom.
5. Set `APPLY_CHANGES = True` only when ready to write CKAN metadata.
6. Set resource upload flags only when ready to upload or upsert CKAN resources.

- Source metadata URL: `https://www.twdb.texas.gov/groundwater/models/gam/ygjk/ygjk.asp`

## Default target values for `notebook_ckan_registration.ipynb`

- Notebook path: `../DSO-Institute-2026/Day-3/Morning/3_folium_mapping.ipynb`
- Source URL: inferred from the notebook's GitHub remote when possible, or overridden with `NOTEBOOK_SOURCE_URL`.
- Existing CKAN entry: empty by default; set `EXISTING_CKAN_ENTRY` to update an existing package.
- Dataset name/title: LLM-generated by default; set `NOTEBOOK_CKAN_DATASET_NAME` or `NOTEBOOK_CKAN_DATASET_TITLE` to override.
